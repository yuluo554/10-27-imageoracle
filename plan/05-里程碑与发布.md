## 三、发布动作序列（M6）

**顺序固定，不可交换**（skill「构建必须排在交付面定稿之后」）：

1. 交付面定稿（`README` 状态行、`LICENSE`、`pyproject.toml`、`CHANGELOG.md` 全部写完）。
2. `plan/RELEASE-M6.md` 写完两栏（§一 tag 前事实 / §二 tag 后追加），覆盖对账表齐。
3. 全量测试 + 两道门 + `tools/verify_gates.py` 变异验证全绿。
4. `rm -rf build dist src/*.egg-info`（无构建产物则跳过），`git archive` 出源码包到中立目录。
5. `commit` → `git tag -a v0.1.0 -m …` → 建 GitHub 公开仓库 → `push origin main` → `push origin v0.1.0`。
6. `gh release create v0.1.0 <tarball> --notes-file <留档导出的正文>`；**附件 sha256 只写 Release 正文**，
   **不写进 tag 树内的文档**（自指失效）。
7. 发布后：`git log --oneline v0.1.0..HEAD` 逐条核对只含非交付面改动；把 run id 逐行追加进留档 §二。

**tag 之后只允许非交付面提交**：`plan/`、`docs/`、`tests/`、`tools/`、`README.md`、`AGENTS.md`。
`src/`、`pyproject.toml` 有差异 = 发布物变了，必须重发版本。
