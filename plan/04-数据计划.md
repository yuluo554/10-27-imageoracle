## 二、真值纪律（本机无外部工具链）

**本机实测（2026-10-27）**：`exiftool` / `jpegtran` / `sharp` / `magick` / `cjpeg` **全部不存在**，
`python` 是 3.8.8 商店占位符。⇒ 题目文档写的 `exiftool -Orientation#=N` 与 `jpegtran -copy all` **不能作为生成路径**。

四条替代纪律：

1. **真值的字节由本仓库自己构造**（`struct.pack`），不调用任何外部 CLI。
   这与 skill「真值的字节不能依赖跑生成器那台机器上的工具链版本」一致：不同版本的 exiftool 会写出不同
   的 IFD 顺序/填充，哈希随之漂移，而"逐字节可复现"是本题的评分项。
2. **真值 = 输入 + 期望值，期望值可由输入独立复算**：每个 fixture 在 `manifest.json` 里写
   `{path, sha256, bytes, triggers:[{module, code, expected}]}`，`expected` 只写"应命中的 code 与关键字段"，
   **不写"我认为它会怎样显示"**（那需要跑消费者）。
3. **生成器 `--check` 位级一致**：`py -3.12 fixtures/gen_all.py --check` 重新生成到内存 →
   与 `manifest.json` 的 `sha256` 逐条比对 + 与上次写盘的冻结产物比对（**两层都断言**）。
   不带 `--check` 才写盘。**`--check` 走的是 `build()`**，自检挂在 `build()` 末尾而不是 `__main__` 下
   （skill 假门族 ⑲）。
4. **生成器确定性**：固定输入、无随机、无时间戳；PNG 的 `tIME` 一律不写；`zlib.compressobj(level=9, wbits=15)`
   固定参数（同版本 Python 输出稳定；**跨版本可能变** → 因此 manifest 的 sha256 是**单版本冻结值**，
   跨解释器矩阵只跑"解析产物一致"，不跑"字节哈希一致"，见 `plan/05` §四）。

**已知边界（必须写进 manifest 的 `notes`）**：

- `m4_icc_truncated.png` 的 `iCCP` 是 zlib 流；首期**不解压**，所以 `icc_header_truncated` 只能由
  **JPEG APP2 / TIFF 34675 / WebP ICCP** 这三条不解压的路径触发。PNG `iCCP` 一律
  `unknown: compressed_profile_not_inspected`。**这是有意的范围限定**，fixture 要同时证明两条行为
  （PNG 走 unknown、JPEG 走 error），否则"范围限定"会退化成"漏实现"。
- WebP `EXIF` 前缀存在性（D10）两支都要有样本，不得只造一支。
- APNG `fcTL`/`fdAT` 是否共享同一 `sequence_number` 序列：`data/README` 标 ⚠️ 待逐字复核。
  **生成器按"共享一个序列"构造**，若实施期复核推翻，则是生成器 bug 而非被测器 bug → 先改生成器。
- **错位样本必须与好样本字节不同**（M5 实测）：`ANIM` 的两种 6 字节写法在 loop=0 时逐字节相同，
  判定器无法区分。`anim_payload_swapped` 改为 8 字节（Loop u32 + Background u32），
  判据落在**载荷长度**这一结构事实上；`gen_container._extra_self_check` 断言两份样本不得字节相同。
