# 模块详设（M2–M6 的契约）

> 模块编号 ↔ 题目文档编号映射见 `plan/05` §一。数值口径（变换矩阵 / ICC 校验项 / 帧单位 / gray / 退出码）
> **只在 `data/README.md` §8 定义**，本文件只写契约与落点。

## 零、公共契约

### 0.1 `Finding`（判决项，全模块统一）

```json
{
  "module": "orientation",
  "code": "orientation_out_of_range",
  "severity": "error",              // error | warning | info | unknown | suspicion
  "confidence": "certain",          // certain | gray | gray-heuristic | single-source
  "message": "orientation value 9 is outside int16u range 1..8",
  "evidence": {
    "spec": "EXIF-TAG274",
    "quote": "6 Rotate 90 CW",
    "location": {"container": "jpeg", "chunk": "APP1", "offset": 37}
  }
}
```

- `evidence` **必填**。`spec` 必须能在 `src/imageoracle/specs/` 里查到（`selftest_evidence_complete` 断言）。
- `location.offset` 一律**绝对文件偏移**（不是块内偏移）。
- 没有 `evidence` 的行 → 该模块的 `selftest_evidence_complete` 判失败（M6 验收硬项）。

### 0.2 报告头（每个 `--json` 输出必带）

`{"tool":{"name":"imageoracle","version":"0.1.0"}, "schema":"1", "generated_at":"<调用方传入或固定串>", "input":{"path":"<相对或入参原样>","size":N,"sha256":"…"}, "findings":[…], "summary":{"error":N,"warning":N,"info":N,"unknown":N,"suspicion":N}}`

- **不写运行时钟**：`generated_at` 默认 `"1970-01-01T00:00:00Z"`（可被 `--generated-at` / `SOURCE_DATE_EPOCH` 覆盖），
  这样双跑逐字节相等才成立。
- 输入路径按**入参原样**输出（不 `abspath`），否则报告会带本机路径（脱敏门会红）。

### 0.3 退出码唯一出口

`src/imageoracle/cli.py` 里**一处**函数 `exit_code_for(findings) -> int`，全部子命令只调它。
口径见 `data/README.md` §8.5（0/1/2/3）。测试逐位断言。

## 一、M2 `orientation`（题目 M1）

**输入**：单文件 + `--json`。支持 JPEG / TIFF / PNG(`eXIf`) / WebP(`EXIF`)；其余 → exit 3。

**读什么**

| 容器 | 位置 |
|---|---|
| JPEG | APP1 `Exif\0\0` → TIFF 头 → IFD0 tag 274；IFD1（缩略图）tag 274；APP1 XMP `http://ns.adobe.com/xap/1.0/\0` 里的 `tiff:Orientation` |
| TIFF | IFD0 / IFD1 tag 274 |
| PNG | `eXIf` chunk 数据**直接**按 TIFF 结构解析（**无** `Exif\0\0` 前缀；D10 待 fixtures 双向验证） |
| WebP | `EXIF` chunk 内做 `Exif\0\0` **前缀探测**（有则跳过 6 字节） |

**输出**

1. 每个来源的原始值：`exif.ifd0.orientation` / `exif.ifd1.orientation` / `xmp.tiff:Orientation`；
2. 应施加变换：`{flip_h, flip_v, rotate_cw_deg}`，**镜像族（2/4/5/7）必须同时给 flip 与 rotate**；
3. 有效宽高：5/6/7/8 交换 W/H；
4. 缺失 → `absent`（**不是** 1）；越界（0、9+、非 int16u）→ `error: orientation_out_of_range`。

**硬验收**

- 8 个样本逐项对 ExifTool 语义（`data/README` §1.1 原文表）。
- 单测：`6 → rotate_cw_deg == 90`（断言文案引用 ExifTool 原文 `Rotate 90 CW`）；`8 → 270`。
- 单测：值 4 的规范形式是 `flip_v=True, rotate=0`（**不做等价化简**，见 §8.1 注记）。

## 二、M3 `double-rotate`（题目 M2）

**判决条件（或关系，报出命中几条）**

| # | 条件 | 置信度 |
|---|---|---|
| 1 | `IFD1.orientation != IFD0.orientation`（两者都存在时） | `certain` |
| 2 | XMP `tiff:Orientation` 与 EXIF tag 274 冲突（值不同；或一方存在且非 1 而另一方缺失） | `certain` |
| 3 | 声明方向与容器自带宽高的"大边位置"启发式不符 | `gray-heuristic`（只出 `suspicion`） |

**输出**：`{condition_hits:[…], certain:[…], heuristic:[…], verdicts:[{consumer, trigger_chain, consequence, evidence}]}`。

**每条 verdict 必须给"软件 × 触发链"**，例如：

- `sharp.autoOrient()`：EXIF 已归 1 但 XMP `tiff:Orientation` 仍在 → 下游读 XMP 的再转一次（#4585）；
- `jpegtran -copy all -rotate 90`：主图转了、IFD1 缩略图 "copied as-is and not transformed"；
- `ImageMagick -auto-orient`："may be rotated wrongly a second time"。

**硬验收**：复现 sharp #4585 与 jpegtran `-copy all`；两族样本**先跑 M2 确认基线**再跑 M3。

## 三、M4 `color`（题目 M3）

**检查项与落点**

| # | 检查 | 结果码（`data/README` §8.2） |
|---|---|---|
| 1 | ICC 存在性（JPEG APP2 多段拼接 + 段号 `i/n` 连续；PNG `iCCP`；WebP `ICCP`；TIFF 34675） | `icc_missing`(info) / `icc_segment_gap`(error) |
| 2 | 128B 头逐字段（`ProfileFileSignature@36`、`ProfileSize` vs 载体长度、`ProfileClass@12`、`ColorSpaceData@16`、`ProfileConnectionSpace@20`、`RenderingIntent@64`） | 见 §8.2 表 |
| 3 | PNG `iCCP` ↔ `sRGB` 并存 | `warning: iccp_srgb_conflict` |
| 4 | `gAMA` / `cHRM` 有无组合 | `info`，逐组合标注 |
| 5 | CMYK JPEG（APP14 `transform`） | `warning: cmyk_jpeg`（附 @amiantos 原话作需求依据，**不作技术依据**） |
| 6 | 位深（JPEG SOF 精度 / PNG IHDR bit depth / WebP 能否不解码读到） | `info` 或 `unknown` |
| 7 | **默认假设表**（7 行，逐行带 `source`） | `info`，见 `data/README` 与 `plan/01` §3 M3 |

**确定性纪律**：不做颜色变换、不引 lcms；风险只出 `risk: high/medium/low/unknown` + 依据，**绝不出具体色值**；
PNG `iCCP` 压缩流首期**不解压**（`unknown: compressed_profile_not_inspected`）。

**硬验收**：lr0 形态复现（`iCCP present (len=N)` / `sRGB absent` / `gAMA`,`cHRM` 有无 + Chrome/Safari 分歧标 `single-source`）；
损坏三类各命中（截断 / `size` 错 / `acsp` 坏）；默认假设表在报告里逐行出现且每行有 `source`。

## 四、M5 `container`（题目 M4）

| # | 检查 | 规范依据 |
|---|---|---|
| 1 | PNG chunk 顺序（IHDR 首 / IEND 末 / PLTE / tRNS / `cHRM,cICP,gAMA,iCCP,sBIT,sRGB` / `bKGD,hIST,tRNS` / `acTL,eXIf,pHYs,sPLT` / `fcTL` / `fdAT`） | PNG-3 Table 7 |
| 2 | CRC = `chunk type + data`（**不含 length**），每个 chunk 都要有 | PNG-3 |
| 3 | IDAT 连续 | PNG-3 |
| 4 | APNG：`num_frames == fcTL count`；首 `fcTL` 序号 0；序号单调无缺口无重复；`delay_den==0→100`；`acTL` 在首 IDAT 前 | Mozilla APNG |
| 5 | WebP：`ANIM`（BGRA、Loop u16=0 无限）、`ANMF` duration 24-bit **ms**、内部边界 | RFC 9649 |
| 6 | GIF：disposal 含 4–7、delay **1/100 s**、GCE 位置与帧序 | GIF89a |
| 7 | JPEG 段顺序（SOI→APPn→DQT/DHT→SOF0/SOF2→SOS）、多 SOS 与 progressive 一致、APP14 位置 | ITU T.81 结构 |
| 8 | 跨格式帧时长归一化到 ms + `unit_mismatch`（10× / 1×） | `data/README` §8.3 |

**输出**：错误清单（`container/chunk`、`offset`、`spec`、`quote`、`severity`）+ 归一化帧时长表。
**硬验收**：每类 2 例；100 ms 三格式（GIF 10 / APNG 10/100 / WebP 100）归一化后都 100；错写报 `unit_mismatch`；
CRC 已知向量单测（`b"IEND"` → `0xAE426082`）。

## 五、M6 `consumers`（题目 M5）

**输入**：M2–M5 的结果。**输出**：

1. **消费者矩阵**（JSON + 人读表）：行 = Chrome / Safari / Firefox / macOS Preview / Windows 照片 /
   ImageMagick / libvips / sharp / exiftran；列 = 会应用方向? / 会应用 ICC? / 会丢哪些 chunk? /
   双重旋转风险 / 动画帧时长解读 / 依据。
2. **风险清单**：`{consumer, risk, severity, evidence, confidence}`。
3. **处理前后 diff**：≥4 条加工命令（`oxipng --strip safe`、`oxipng --strip all`、`sharp.rotate()`、`exiftran`）。
4. 退出码按全局纪律。

**硬验收**：每行 `evidence.kind ∈ {spec, tool-doc, hn-quote}`；`tool-doc` 必须 URL + 原文片段；
`confidence ∈ {certain, single-source, gray}`；**无 evidence 的行让 `selftest_evidence_complete` 失败**。
矩阵内容来自 `data/README.md` 台账，不来自运行时猜测；报告头写工具版本与星数快照日期。
