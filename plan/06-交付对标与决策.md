## 四、决策记录（追加，主表见 `plan/00`）

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| D11 | 测试框架 | 标准库 `unittest`，**不引入 pytest** | 零依赖可证伪（无网容器里能跑通即证明"零第三方 import"） |
| D12 | 版本号真源 | `src/imageoracle/__init__.py` + `pyproject.toml` 两处，测试断言相同 | 单一来源在纯 stdlib 下没有构建期注入；两处 + 一条测试等价 |
| D13 | 发布附件 | 手工源码包（`git archive --format=tar.gz`） | GitHub 自动 Source code 包的 sha256 本地复算不出来 |
| D14 | CI 矩阵 | Python 3.10 / 3.12 × ubuntu / windows + 一个 `offline` job | 覆盖最低支持版本与实际开发版本；offline job 证零网络 |
| D15 | 报告 `generated_at` 默认值 | `"1970-01-01T00:00:00Z"` | 确定性优先；真实时间由调用方传入 |
| D16 | 规范条款 ID 体系 | `EXIF-TAG274` / `ICC-HEAD` / `PNG3-T7` / `PNG3-CRC` / `APNG-SEQ` / `WEBP-ANMF` / `GIF89A-GCE` | evidence.spec 必须可查；ID 在 `specs/` 里逐条对应原文 |
| D17 | **M3 条件 2 的"一方缺失"分支不实现** | 只认"EXIF 274 与 XMP `tiff:Orientation` **都存在且值不同**" | 题目原文写作"值不同；或一方存在且非 1 而另一方缺失"。照抄会把"EXIF=6 且无 XMP"（**最常见的正常照片**）全判 `certain` → 与出口门"M2 好样本不产生 certain"和 K3（`absent` ≠ `=1`）直接冲突。收窄后仍完整覆盖 sharp #4585（EXIF=1、XMP=6，两侧都存在）。原文照录在 `plan/03` §二 引用块里，并注明"已被收窄"，避免日后被当成漏实现 |
| D18 | **M3 条件 3 已知假阳性被接受** | 规范的手机竖拍（存储宽>高 + tag 5/6/7/8）也命中条件 3 | 该条件只出 `suspicion`、不进退出码、不进 `certain` 列表，因此不会把正常图报成"确定转错"；收紧它需要解码像素（硬约束外）。代价写进 `data/README` §8.6，是声明而非隐瞒 |
| D20 | **M6 的 `tool-doc` 只给已逐字复核的页面** | 只有 sharp `rotate()` 与 ImageMagick `-auto-orient` 两行挂 `tool-doc`（URL 见 `data/README` §3.1）；exiftran / oxipng / jpegtran / libvips 的参数页取不到（404 / 连接重置 / 只有索引页）→ 改挂 `spec`（已登记条款）或 `hn-quote`，并在 §9 #13 登记 | 矩阵的行若有 4 行挂 `tool-doc` 却没 URL，等于把"看起来像官方页"当证据；宁可让 `tool-doc` 只有 2 行，也不编地址。取不到第一方文档的消费者（Firefox / macOS Preview / Windows 照片 / libvips autorot）在矩阵里一律 `unknown` + `gray`，不按常识补 `yes` |
| D19 | **M4 `cmyk_jpeg` 的触发条件收窄为"四分量 JPEG"** | 只认 `SOF.components == 4`，不认"存在 APP14 `transform` 字段" | 题目原文（`plan/01` §3 M3 第 5 项）写"存在 Adobe APP14 `transform` 字段时标 warning"。但最常见的 YCbCr Adobe JPEG **也带 APP14**（`transform=1`，见 `m5_jpeg_app14_pos.jpg` 一类样本），照抄会把**好样本**误报成 CMYK，与出口门"M2 好样本不产生 error/warning"冲突。APP14 `transform` 仍作为 `facts.app14_transform` 报出，只是不作触发依据。原文照录在 `data/README` §8.2 里并注明"已收窄" |
